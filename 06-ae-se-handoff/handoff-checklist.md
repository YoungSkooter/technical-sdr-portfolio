# SDR Handoff Checklist

> Use this checklist before advancing a simulated opportunity to an AE or SE.

---

## A. Account

- [ ] Account identified
- [ ] ICP fit established
- [ ] Relevant technical environment identified
- [ ] Relevant trigger or signal identified
- [ ] Research sources documented

---

## B. Persona

- [ ] Prospect role identified
- [ ] Persona responsibilities understood
- [ ] Relationship to problem understood
- [ ] Additional stakeholders identified
- [ ] Economic buyer status known or explicitly marked unknown

---

## C. Problem

- [ ] Problem clearly stated
- [ ] Problem tied to a specific workflow
- [ ] Current-state workflow documented
- [ ] Manual vs automated steps identified
- [ ] Problem distinguished from hypothesis

---

## D. Impact

- [ ] Impact discussed
- [ ] Impact quantified where possible
- [ ] Quantification source documented
- [ ] Simulated numbers clearly labeled
- [ ] Business impact separated from technical symptoms

---

## E. Urgency

- [ ] Timeline discussed
- [ ] Trigger identified
- [ ] Current initiative identified
- [ ] Priority confirmed or marked unknown
- [ ] No artificial urgency created

---

## F. Existing Solution

- [ ] Current tooling identified
- [ ] Existing automation understood
- [ ] Current solution strengths identified
- [ ] Gaps/workarounds identified
- [ ] Replacement vs augmentation unknowns documented

---

## G. Technical Context

- [ ] Cloud environment
- [ ] Infrastructure
- [ ] Relevant applications
- [ ] Security systems
- [ ] Data sources
- [ ] Workflow integrations
- [ ] Automation boundary
- [ ] Technical constraints
- [ ] Unknowns

---

## H. AE Handoff

AE knows:

- [ ] Why this account
- [ ] Why this persona
- [ ] Why now
- [ ] Problem
- [ ] Impact
- [ ] Stakeholders
- [ ] Existing solution
- [ ] Opportunity status
- [ ] Unknown commercial information
- [ ] Recommended next step

---

## I. SE Handoff

SE knows:

- [ ] Current workflow
- [ ] Technical environment
- [ ] Systems involved
- [ ] Automation boundary
- [ ] Technical problem
- [ ] Integration requirements
- [ ] Security requirements
- [ ] Technical unknowns
- [ ] Technical validation objective

---

# Handoff Quality Test

Before sending the handoff, ask:

> **Could the AE understand the opportunity without reading the entire research file?**

> **Could the SE understand the technical workflow without starting discovery from zero?**

> **Have I clearly separated verified facts, prospect-confirmed information, hypotheses, and unknowns?**

If the answer is yes, the handoff is ready.

---

# Evidence Classification

| Label | Meaning |
|---|---|
| VERIFIED / PUBLIC FACT | Supported by public information |
| PROSPECT-CONFIRMED | Stated by the simulated prospect |
| HYPOTHESIS | SDR inference requiring validation |
| SIMULATED | Fictional scenario information |
| UNKNOWN | Not yet established |
| SALES ACTION | What the SDR should do next |
