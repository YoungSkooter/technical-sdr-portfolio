# Simulated Prospect Response

> **SIMULATION**
>
> This response is fictional and does not represent an actual
> communication from Figma or a Figma employee.

## Hypothetical Response

**Prospect:** Security Engineering Manager

> "Thanks for reaching out. We've already invested quite a bit in
> automating security investigations, so I'm not sure we have a need
> for another platform.
>
> There are still some cases where engineers need to pull additional
> context from different systems, particularly when an investigation
> crosses cloud infrastructure and engineering ownership.
>
> Our security engineers usually handle the initial investigation,
> but Platform Engineering gets involved when infrastructure changes
> are required."

---

# What We Learned

The response gives us several useful signals.

## Signal 1 — Existing Investment

The prospect already has security automation.

**Implication:**

Do not position the conversation as:

> "You need security automation."

Instead investigate what remains outside the automation.

---

## Signal 2 — Potential Workflow Gap

The prospect says some investigations still require additional
context.

**Implication:**

The original hypothesis has received partial validation.

It is still not enough to establish a sales opportunity.

---

## Signal 3 — Cross-Team Workflow

Security Engineering investigates.

Platform Engineering becomes involved when infrastructure changes are
required.

**Implication:**

There may be a security → platform handoff worth investigating.

---

## Signal 4 — Existing Platform

The prospect says they are unsure about needing another platform.

**Implication:**

The next conversation should focus on workflow gaps rather than
immediately positioning a replacement.

---

# Qualification Questions

The next conversation should establish:

1. How often does this happen?
2. What additional context is required?
3. Which systems provide that context?
4. How much manual effort is involved?
5. What happens after the investigation?
6. How does ownership get determined?
7. How frequently does Platform Engineering become involved?
8. Is this currently a priority?
9. Who else is involved?
10. What would an improved workflow look like?
